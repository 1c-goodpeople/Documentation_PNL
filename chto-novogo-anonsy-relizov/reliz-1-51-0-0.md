## Согласование

Система согласования полностью переработана. Теперь это отдельный раздел **1C:P&L -> Согласование**, через который проходят заявки на оплату, реестры платежей и договоры контрагентов.

### Как теперь работает

1. **Маршруты с этапами.** Администратор один раз настраивает маршрут: этапы, согласующих на каждом этапе и правило закрытия этапа -- «Все согласующие», «Любой из согласующих» или «Кворум». Этапы идут по очереди: следующие согласующие получают документ только после закрытия предыдущего этапа.

2. **Автоматический подбор маршрута.** При отправке система сама выбирает маршрут по типу документа, периоду действия и условиям, например по организации. Перед отправкой инициатор видит схему маршрута: этапы и согласующих.

3. **Единое рабочее место согласующего.** В разделе «Мои согласования» собраны все документы, которые ждут вашего решения. В карточке документа есть вкладки «Прогресс маршрута» и «История»: видно, на каком этапе документ, кто уже принял решение и кто согласует дальше. Решение можно принять по нескольким документам сразу.

4. **Возврат на доработку.** Заявку на оплату можно вернуть инициатору с комментарием. Инициатор исправляет заявку и отправляет заново, она проходит маршрут с первого этапа. В списке заявок появился статус «На доработке».

5. **Реестр платежей согласуется по строкам.** Каждый платёж проходит маршрут отдельно: один можно согласовать, другой отклонить. В таблице реестра у каждого платежа появились ссылки «Открыть маршрут» и «Открыть историю».

## Косвенные расходы в ОПиУ

Распределение косвенных расходов в отчёте ОПиУ работает по-новому. Аренда офиса, зарплата бухгалтерии, связь и другие общие расходы делятся по организациям, подразделениям, доп. аналитике, проектам и разделам проекта пропорционально выбранной базе, например выручке.

### Что изменилось

1. **Два способа распределения.** В карточке группы косвенных расходов появилось поле **«Распределять»**. Способ «Распределять всю сумму» делит всю сумму группы, как раньше. Способ «Распределять только нераспределенное» оставляет на месте суммы, у которых аналитика уже указана в документах, и делит только остаток.

2. **Исключения.** При способе «Распределять только нераспределенное» можно указать организации, подразделения, доп. аналитику, проекты и разделы проектов, на которые косвенные расходы не распределяются. Исключённое значение не участвует в базе, и его доля уходит остальным значениям.

3. **Вложенные группы.** Внутрь группы косвенных расходов можно вложить подгруппы любой глубины, например «Административные расходы» и «Коммерческие расходы». Статьи всех подгрупп тоже распределяются.

4. **Сумма по колонкам равна итогу.** Если часть базы не разнесена по аналитике, например часть выручки не указана на проект, колонка «Без проекта» получает свою долю косвенных расходов. Копейки округления дописываются в последнюю колонку, поэтому сумма колонок совпадает с колонкой «Итого».

5. **Формулы считаются по распределённым суммам.** Операционная прибыль (EBITDA), чистая прибыль и рентабельность в каждой колонке учитывают распределённые косвенные расходы.

## MCP: данные P&L для ИИ-ассистентов

В модуле появился блок **MCP**. Он подключает данные P&L к ИИ-ассистентам -- Claude, Cursor и другим программам с поддержкой протокола MCP. Вопрос о финансах задаётся ассистенту обычным языком, а цифры он берёт прямо из базы 1С.

### Что умеет

1. **Отвечает на вопросы по отчётам.** Ассистенту доступны ОПиУ, БДР, ДДС, БДДС, платёжный календарь, проекты и договоры. Например: «Какая чистая прибыль и рентабельность за полугодие?», «Где самое большое отклонение от бюджета во втором квартале?», «Какие платежи просрочены?».

2. **Считает как отчёты модуля.** Суммы считаются по структуре отчёта, без НДС, с формулами и распределёнными косвенными расходами. Период, разбивка по месяцам и кварталам, разрезы по организациям, проектам, статьям и контрагентам задаются прямо в вопросе.

3. **Сравнивает план и факт.** По БДР и БДДС ассистент показывает план, факт, отклонение и процент исполнения.

4. **Строит графики.** По просьбе «построй график» ассистент собирает дашборд в оформлении P&L. Файл открывается в браузере и вставляется в «Поле HTML документа» 1С без правок.

5. **Только чтение.** Ассистент получает только данные, запрошенные для ответа, и не может ничего изменить в базе. Сервис включается флажком в настройках и работает под отдельным пользователем 1С.

Блок доступен в версиях **КОРП** и **КОРП BI**.
