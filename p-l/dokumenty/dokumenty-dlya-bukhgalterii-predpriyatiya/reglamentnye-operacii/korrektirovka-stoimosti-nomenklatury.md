---

Регламентная операция **«Корректировка стоимости номенклатуры»** выполняется при закрытии месяца в **1С:Бухгалтерия предприятия**. Она уточняет стоимость списанных материалов и товаров, и часть этой корректировки попадает на затратные счета -- 20.01, 23, 25, 26.

По умолчанию такие суммы отражаются в P&L одной статьёй -- той, что задана для операции в настройке [Регламентные операции](./_index). Если производство ведётся по нескольким номенклатурным группам или затраты разделяются по статьям затрат, одной статьи мало: в ОПиУ вся корректировка попадает в одну строку и не разносится по направлениям.

Механизм **«Соответствие параметров по корректировке стоимости номенклатуры»** решает эту задачу. Он задаёт правила, по которым система сама подставляет статью и аналитику в зависимости от номенклатурной группы и статьи затрат из проводки.

## **Где находятся настройки**

1. Перейдите в раздел **Настройки** -> **P&L** -> вкладка **ОПиУ**.

2. Откройте блок **«Регламентные операции»**.

3. Выберите пункт **«Соответствие параметров по корректировке стоимости номенклатуры»**.

В этом же блоке находятся настройки **«Соответствие статей регламентным операциям»** и **«Соответствие статей РБП по бухгалтерскому учету»**.

:::tip 

Блок «Регламентные операции» отображается только в **1С:Бухгалтерия предприятия**.

:::

## **Структура правила**

Каждая запись -- это условие вида «Если … то …».

#### **Условия (блок «Если»)**

-  **Номенклатурная группа** -- номенклатурная группа из проводки по дебету затратного счёта.

-  **Статья затрат** -- статья затрат из той же проводки.

Можно заполнить один параметр или оба. Если заполнены оба, правило сработает только при совпадении обоих значений.

#### **Результат (блок «Тогда»)**

-  **Статья** -- статья, на которую попадёт сумма корректировки.

-  **Доп. аналитика** -- заполняется, если раздел включён в настройках P&L. Название поля берётся из настроек.

-  **Проект** и **Раздел** -- заполняются, если в настройках P&L включён раздел «Проекты».

## **Как это работает при проведении**

1. При проведении регламентной операции система берёт проводки документа, у которых по дебету стоит счёт **20\.01, 23, 25, 26** или их субсчёт. Из проводки читаются номенклатурная группа и статья затрат.

2. Для каждой такой строки подбирается правило. Если подходит несколько правил, выигрывает то, в котором заполнено больше условий: правило «номенклатурная группа + статья затрат» перекрывает правило, заданное только по статье затрат.

3. Если правило найдено, в движения P&L попадают статья и аналитика из него.

4. Если правила нет или статья в нём не заполнена, берётся статья из настройки **«Соответствие статей регламентным операциям»** для этой операции.

5. Если не заполнено ни то, ни другое -- движение по строке не формируется, и сумма в ОПиУ не попадает.

Суммы отражаются в ОПиУ методом начисления, как и остальные регламентные операции.

:::tip Важные замечания

Правило, в котором не заполнено ни одно условие, не сохраняется: хотя бы одно из полей «Номенклатурная группа» или «Статья затрат» должно быть указано.

Правила применяются при проведении документа. После того как вы добавили или изменили правила, перепроведите регламентные операции за нужный период -- ранее проведённые документы сами не пересчитаются.

Настройка работает вместе с **«Соответствие статей регламентным операциям»**, а не вместо неё: вторая настройка остаётся запасным вариантом для строк, под которые не подошло ни одно правило, и единственным -- для остальных видов регламентных операций.

:::
