В **1С:Бухгалтерии предприятия** для зарплатных документов можно настроить правила подбора статей и аналитики PnL. Настройка называется **«Соответствие параметров заработной платы по статьям»**. Правила используются при расчёте движений PnL; само проведение не записывает рассчитанные значения в строки документа «Отражение зарплаты в бухучете».

## Где находится настройка

Откройте **Настройки → P&L → ОПиУ → Учёт заработной платы → Соответствие параметров заработной платы по статьям**. В документе «Отражение зарплаты в бухучете» настройку также открывает команда **«Настроить соответствия PnL»** в панели таблицы начисленной зарплаты и взносов.

## Как заполнить правило

В одной записи укажите условия, по которым система найдёт правило, и значения, которые она должна подставить.

### Условия соответствия

1. Подразделение.
2. Вид операции — для «Отражения зарплаты в бухучете».
3. Способ отражения зарплаты в бухучёте.
4. Вид начисления для налогового учёта.

Можно заполнить только нужные условия. Пустое условие правила подходит к любому значению строки; хотя бы одно условие должно быть заполнено. Старые правила без вида операции продолжают подходить для любого вида операции в документе «Отражение зарплаты в бухучете».

### Что заполняется из соответствия

Основная статья ДДС, статьи взносов по единому тарифу и на несчастный случай, доп. аналитика, проект и раздел проекта.

Заполняйте только те условия, которые нужны для различения правил. Например, общее правило можно задать по подразделению, а более точное -- по подразделению и способу отражения.

## Как правило выбирается

- В документе **«Отражение зарплаты в бухучете»** сопоставляются четыре условия строки: подразделение, вид операции, способ отражения и вид начисления для налогового учёта. Выбирается правило с наибольшим числом совпавших заполненных условий. При равной точности нескольких правил соответствие считается неоднозначным; первое попавшееся правило не применяется.
- В документе **«Начисление зарплаты»** действует прежний подбор по подразделению начисления или начисления по договору, способу отражения и виду начисления для налогового учёта. Правила с заполненным видом операции пропускаются. При равной точности остаётся первое найденное правило.

## Приоритет ручных значений

Для каждого из шести реквизитов PnL применяется порядок **строка → шапка → правило**. Правило заполняет только поле, оставшееся пустым после проверки строки и шапки. Если основная статья для строки уже есть в ней или в шапке, отсутствие подходящего правила для этой строки само по себе не препятствует движению PnL.

## Что заполнится в документах

При проведении **«Начисления зарплаты»** и **«Отражения зарплаты в бухучете»** правило помогает разнести расходы по PnL. При создании **«Отражения заработной платы в УУ»** на основании любого из этих документов значения подбираются для строк управленческого документа.

Если основная статья не найдена для хотя бы одной строки с суммой зарплаты или взносов в «Отражении зарплаты в бухучете», движения PnL этого документа очищаются. В «Начислении зарплаты» та же очистка происходит, если основная статья отсутствует у ненулевого начисления или начисления по договору. **Стандартное проведение и бухгалтерские проводки из-за PnL не блокируются.** Если отсутствует только отдельная статья взносов, пропускается расход PnL по этому виду взносов, а остальные движения сохраняются.

В «Отражении зарплаты в бухучете» команда **«Заполнить реквизиты PnL»** в панели таблицы позволяет до проведения увидеть подобранные значения. Повторное нажатие заменяет все шесть полей каждой содержательной строки, включая значения, введённые вручную; используются шапка и правило. Команда обновляет колонку «Реквизиты PnL», но сама не записывает и не проводит документ. После исправления правила нажмите её ещё раз, затем сохраните или проведите документ.
