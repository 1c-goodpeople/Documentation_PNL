Документ **«Требование-накладная»** в конфигурации **«Бухгалтерия предприятия»**. Отражает стоимость списанных материалов. Статья расходов выбирается из шапки либо соответствия параметров БП.

Общий порядок применения правил: [как заполняются реквизиты документов](../kak-zapolnyayutsya-rekvizity-dokumentov). Здесь приведён порядок для этого документа.

## Реквизиты и приоритеты

| Реквизит | Где задаётся | Как используется и какой источник выше |
|---|---|---|
| Дата принятия к управленческому учёту | Шапка | Дата УУ → дата документа в обычном начисленном расчёте. Дата строки ручного распределения выбирается отдельным путём. |
| Доп. аналитика | Шапка | Заполненное поле шапки → соответствие параметров БП. |
| Проект | Шапка | Заполненное поле шапки → соответствие параметров БП. |
| Раздел проекта | Шапка | Заполненное поле шапки → соответствие параметров БП. |
| Статья P&L | Шапка | Заполненное поле шапки → соответствие параметров БП. |
| Отразить товар в проект | Шапка | Управляет предусмотренной документом детализацией товаров для проекта. Сам по себе не выбирает статью расходов и не создаёт НЗП. |
| Отражать в НЗП | Шапка | Признак шапки. В обычной автоматической ветке требования он не передаётся в созданный расход; особенности НЗП описаны ниже. |

## Заполнение и запись

Значения задаются в доступном блоке «Реквизиты P&L» и реквизитах строки, где они предусмотрены. Автоправило ОПиУ с непустым значением может изменить поле шапки до сохранения; движение читает уже сохранённое значение. Этот этап отличается от выбора следующего источника для пустого поля.

- При копировании дата принятия к управленческому учёту очищается. Для новой копии проверьте период отражения отдельно.

## Особенности документа

- Подразделение движения: подразделение затрат → подразделение организации документа.
- В действующей автоматической ветке признак «Отражать в НЗП» шапки/соответствия не присваивается созданному расходу. Флажок документа поэтому не гарантирует автоматический перенос материалов в НЗП; ручное распределение с признаком НЗП использует отдельный путь.

## Контроль результата

После заполнения проверьте статью, сумму, период и аналитику движений P&L. Исключённая статья не заменяется умолчанием. Для пересчёта существующих данных применяйте явную команду P&L; изменение настройки само по себе не пересчитывает прошлые документы.
