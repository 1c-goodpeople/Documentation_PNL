Документ **«Возврат товаров от клиента»** в конфигурации **«Управление торговлей»**. Отражает возврат выручки и восстановление себестоимости. Восстановленная себестоимость записывается в доходы P&L.

Общий порядок применения правил: [как заполняются реквизиты документов](../kak-zapolnyayutsya-rekvizity-dokumentov). Здесь приведён порядок для этого документа.

## Как заполняются реквизиты документа: приоритетность заполнения

### Статья, доп. аналитика, проект и раздел проекта

1. Из шапки документа.

Шапка может заполняться вручную, при создании на основании или автоправилом ОПиУ перед записью.

### Дата принятия к управленческому учёту

1. Из поля «Дата принятия к управленческому учёту» в шапке документа.
2. Из даты документа, если дата принятия к управленческому учёту не заполнена.

При обычном расчёте по начислению используется этот порядок. При ручном распределении дата выбирается из строки распределения.

### Статья себестоимости

1. Из шапки документа.
2. Из настройки «Статья себестоимости по умолчанию», если статья в шапке не заполнена.

Сумма себестоимости берётся из типового учёта. Особенности заполнения пустой шапки описаны ниже.

## Заполнение и запись

Значения задаются в доступном блоке «Реквизиты P&L» и реквизитах строки, где они предусмотрены. Автоправило ОПиУ с непустым значением может изменить поле шапки до сохранения; движение читает уже сохранённое значение. Этот этап отличается от выбора следующего источника для пустого поля.

- При копировании дата принятия к управленческому учёту очищается. Для новой копии проверьте период отражения отдельно.
- В действующей версии пустая статья себестоимости шапки может заполняться настройкой по умолчанию при создании/записи этого документа. При расчёте это уже заполненное поле шапки. Правило «умолчание только в движениях» реализовано отдельно для розницы и реализации БП и не распространяется автоматически на этот документ.

## Контроль результата

После заполнения проверьте статью, сумму, период и аналитику движений P&L. Исключённая статья не заменяется умолчанием. Для пересчёта существующих данных применяйте явную команду P&L; изменение настройки само по себе не пересчитывает прошлые документы.
