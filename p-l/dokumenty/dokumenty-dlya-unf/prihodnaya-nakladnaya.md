Документ **«Приходная накладная»** в конфигурации **«Управление нашей фирмой»**. Отражает предусмотренные операцией приходной накладной расходы и возвраты. Отдельная себестоимость в этой ветке рассчитывается для возврата от покупателя, комиссионера или переработчика.

Общий порядок применения правил: [как заполняются реквизиты документов](../kak-zapolnyayutsya-rekvizity-dokumentov). Здесь приведён порядок для этого документа.

## Как заполняются реквизиты документа: приоритетность заполнения

### Статья, доп. аналитика, проект и раздел проекта

При ручном распределении используются его строки — соответствие счетов не применяется.

В автоматическом режиме при поступлении от поставщика каждое поле заполняется независимо:

1. Из шапки документа.
2. Для услуг — из настройки «Соответствие счетов и статей» по счёту учёта затрат номенклатуры, если соответствующее поле шапки пустое.

Например, если статья в шапке заполнена, а дополнительная аналитика нет, статья сохраняется из шапки, а аналитика подбирается по счёту. Заполненные поля шапки соответствие не заменяет. Подбор используется при формировании движений P&L и не заполняет шапку документа.

Шапка может заполняться вручную, при создании на основании или автоправилом ОПиУ перед записью. При расчёте учитываются значения после применения автоправила.

## Как настроить соответствие для услуг

Настройка находится в **P&L → Настройки → ОПиУ → Соответствие параметров → Соответствие счетов и статей**.

1. Откройте карточку номенклатуры услуги. На вкладке **«Счета учёта»** укажите **счёт учёта затрат**.
2. В настройке **«Соответствие счетов и статей»** добавьте запись с этим счётом управленческого учёта. Укажите статью P&L и, при необходимости, дополнительную аналитику, проект и раздел проекта.
3. В приходной накладной с операцией поступления от поставщика оставьте пустыми те поля P&L в шапке, которые нужно подбирать по услугам. Проведите документ и проверьте движения P&L.

Услуги с разными счетами затрат могут отражаться по разным статьям и аналитикам в одной накладной. Если статья задана в шапке, соответствие можно использовать только для недостающей аналитики или проекта.

Товарная часть обрабатывается по прежним правилам. В смешанной накладной суммы товаров и услуг учитываются отдельно, без повторного отражения общей суммы документа. Для возвратов сохраняется прежний порядок расчёта.

Если статья в шапке пустая и после подбора хотя бы у одной услуги статья не определена, все движения P&L этого документа очищаются, включая прежние движения при перепроведении. Частичная сумма расходов в отчёт не попадает. Пустые дополнительная аналитика, проект или раздел сами по себе не вызывают очистку. Новая проверка соответствий не запрещает типовое проведение и не меняет типовые движения.

## Даты и себестоимость

### Дата принятия к управленческому учёту

1. Из поля «Дата принятия к управленческому учёту» в шапке документа.
2. Из даты документа, если дата принятия к управленческому учёту не заполнена.

При обычном расчёте по начислению используется этот порядок. При ручном распределении дата выбирается из строки распределения.

### Статья себестоимости

1. Из шапки документа.
2. Из настройки «Статья себестоимости по умолчанию», если статья в шапке не заполнена.

Сумма себестоимости берётся из типового учёта. Особенности заполнения пустой шапки описаны ниже.

## Заполнение и запись

Значения задаются в доступном блоке «Реквизиты P&L» и реквизитах строки, где они предусмотрены. Автоправило ОПиУ с непустым значением может изменить поле шапки до сохранения; движение читает уже сохранённое значение. Этот этап отличается от выбора следующего источника для пустого поля.

- При копировании дата принятия к управленческому учёту очищается. Для новой копии проверьте период отражения отдельно.
- В действующей версии пустая статья себестоимости шапки может заполняться настройкой по умолчанию при создании/записи этого документа. При расчёте это уже заполненное поле шапки. Правило «умолчание только в движениях» реализовано отдельно для розницы и реализации БП и не распространяется автоматически на этот документ.

## Контроль результата

После заполнения проверьте статью, сумму, период и аналитику движений P&L. Исключённая статья не заменяется умолчанием. Для пересчёта существующих данных применяйте явную команду P&L; изменение настройки само по себе не пересчитывает прошлые документы.
