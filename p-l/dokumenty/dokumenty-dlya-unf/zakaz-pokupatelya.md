Документ **«Заказ покупателя»** в конфигурации **«Управление нашей фирмой»**. Хранит данные основания и/или планового платежа. Факт дохода, расхода и себестоимости формируют последующие документы или соответствующие типовые движения.

Общий порядок применения правил: [как заполняются реквизиты документов](../kak-zapolnyayutsya-rekvizity-dokumentov). Здесь приведён порядок для этого документа.

## Как заполняются реквизиты документа: приоритетность заполнения

### Доп. аналитика

1. Из соответствующей строки табличной части — для реквизитов этой строки.
2. Из шапки документа — для реквизитов шапки.

Где заполняется: шапка документа; таблица «Платежный календарь».

Значения используются в плановой аналитике или передаются в созданный документ. Для планового отражения и создания на основании используются отдельные пути заполнения. Выбора статьи фактической себестоимости в этой ветке нет.

### Статья, проект и раздел проекта

1. Из шапки документа — для реквизитов шапки.

Значения используются в плановой аналитике или передаются в созданный документ. Для планового отражения и создания на основании используются отдельные пути заполнения. Выбора статьи фактической себестоимости в этой ветке нет.

### Дата по графику

1. Из поля «Дата по графику» в шапке документа.
2. Из даты документа, если поле пустое и для документа предусмотрено заполнение при записи.

Это дата планового события. Она сама по себе не заменяет дату фактического движения P&L.

### Статья платежа

1. Из строки платёжного календаря заказа.

Где заполняется: таблица «Платежный календарь».

В плановом платеже используется вместе с датой оплаты и суммой этой строки.

## Заполнение и запись

Значения задаются в доступном блоке «Реквизиты P&L» и реквизитах строки, где они предусмотрены. Автоправило ОПиУ с непустым значением может изменить поле шапки до сохранения; движение читает уже сохранённое значение. Этот этап отличается от выбора следующего источника для пустого поля.

- Если дата по графику не заполнена, при записи в неё подставляется дата документа.

## Особенности документа

- При включённом «Запланировать оплату» в календарь P&L записываются дата, статья, доп. аналитика и сумма первой строки типового платежного календаря; организация, банк, контрагент и договор — из заказа.
- Пустая дата по графику заполняется датой заказа. Она не заменяет дату оплаты строки платежного календаря.

## Контроль результата

После заполнения проверьте статью, сумму, период и аналитику движений P&L. Исключённая статья не заменяется умолчанием. Для пересчёта существующих данных применяйте явную команду P&L; изменение настройки само по себе не пересчитывает прошлые документы.
