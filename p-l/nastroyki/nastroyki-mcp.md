Блок **MCP** открывает данные модуля P&L для ИИ-ассистентов: Claude, Cursor и других программ, которые поддерживают протокол MCP (Model Context Protocol). После настройки ассистенту можно задавать вопросы о финансах компании обычным языком, а он сам берёт нужные цифры из базы 1С.

:::info 

Блок доступен только в версии **КОРП** 

:::

## Для чего нужен блок

Без MCP, чтобы ответить на вопрос «какая у нас чистая прибыль за полгода и почему в марте она просела», нужно открыть отчёт, выставить период и структуру, выгрузить данные и разобрать их вручную.

С MCP вопрос задаётся ассистенту в чате. Ассистент сам запрашивает у 1С нужные строки отчёта за нужный период, сравнивает месяцы, раскладывает сумму по проектам или статьям и отвечает с цифрами. По просьбе он строит график или дашборд в оформлении P&L.

Сервис MCP работает только на чтение: ассистент может запрашивать доступные ему показатели, но не может изменять данные в базе через этот сервис.

## Что получит клиент

Ассистенту доступны данные основных блоков модуля:

| Блок                | Что можно спросить                                                                                                                                |
|---------------------|---------------------------------------------------------------------------------------------------------------------------------------------------|
| ОПиУ                | Выручка, расходы, EBITDA, чистая прибыль, рентабельность за любой период, по месяцам, кварталам, по организациям, проектам, статьям, контрагентам |
| БДР                 | Плановые значения по строкам бюджета и план-факт с отклонением и процентом исполнения                                                             |
| ДДС                 | Поступления и платежи по строкам отчёта ДДС, по видам деятельности и в любом разрезе                                                              |
| БДДС                | План движения денег и план-факт                                                                                                                   |
| Платёжный календарь | Список платежей, выполнено, запланировано и просрочено, статус оплаты и согласования                                                              |
| Проекты             | Список и карточка проекта, план по смете, фактические доходы и расходы отдельно по начислению и по деньгам                                        |
| Договоры            | Список договоров, карточка, график платежей и его исполнение                                                                                      |
| Дашборды            | Готовые графики и дашборды в фирменном оформлении P&L. Файл открывается в браузере и вставляется в «Поле HTML документа» 1С без правок            |

Примеры вопросов:

-  «Что у нас по выручке с января по июнь помесячно?»

-  «Покажи чистую прибыль и рентабельность за полугодие и построй график».

-  «Сравни план и факт по БДР за второй квартал. Где самое большое отклонение?»

-  «Какие платежи просрочены на сегодня?»

-  «Какие проекты отстают от сметы по расходам?»

-  «Сколько по проекту начислено доходов за март и сколько денег поступило?»

Показатели ОПиУ, ДДС и бюджетов рассчитываются по настройкам соответствующих отчётов. Для проекта ассистент может отдельно запросить доходы и расходы по начислению и по кассовому методу. Без дат он получит факт за весь срок проекта. Для одного месяца нужно указать начало и конец месяца: эти даты ограничивают только факт, а план проекта остаётся полной сметой. Кассовые доходы и расходы проекта берутся из регистров доходов и расходов по кассовому методу; отчёт ДДС формируется по своей структуре.

## Как настроить

### Шаг 1. Опубликуйте базу на веб-сервере

Ассистент обращается к 1С через HTTP-сервис модуля. Если база уже опубликована на веб-сервере для веб-клиента или обменов, используйте эту публикацию.

При публикации базы в Конфигураторе (**Администрирование -> Публикация на веб-сервере**) включите флажок **«Публиковать HTTP сервисы расширений по умолчанию»**. Без него сервис модуля не будет доступен снаружи.

Адрес сервиса имеет вид:

`http://<адрес сервера>/<имя публикации>/hs/mcp_pnl/v2`

### Шаг 2. Создайте пользователя для ассистента

Заведите в 1С отдельного пользователя, под которым ассистент будет обращаться к базе, например «MCP-ассистент». Отдельный пользователь нужен, чтобы не передавать ассистенту логин и пароль сотрудника.

Назначьте пользователю роли:

1. **МСР: агент (только чтение)** -- доступ к сервису MCP.

2. **Управление финансами (Аудитор)** -- чтение данных модуля P&L.

### Шаг 3. Включите сервис в настройках P&L

1. Откройте **1C:P&L -> Настройки** и выберите блок **«MCP»**.

2. Установите флажок **«Использовать MCP сервис»**. Пока флажок снят, сервис отклоняет все запросы ассистента.

3. Выберите состояние флажка **«Передавать персональные данные»**. Он управляет именами справочников в ответах MCP; правила приведены в таблице ниже. Выключенный флажок не отключает сам сервис.

4. На странице показан шаблон **адреса сервиса**. Подставьте адрес публикации вашей базы в `PNL_MCP_URL` при подключении ассистента на шаге 5.

#### Как передаются имена справочников

Имена в ответе зависят от положения флажка:

| Справочник 1С                            | Флажок установлен    | Флажок снят                                                             | Если источник подмены пуст |
|------------------------------------------|----------------------|-------------------------------------------------------------------------|----------------------------|
| **Контрагенты** (`Контрагенты`)          | Обычное наименование | Реквизит **«Наименование (PnL)»** в карточке контрагента                | Код контрагента            |
| **Физические лица** (`ФизическиеЛица`)   | Обычное наименование | Реквизит **«Наименование (PnL)»** в карточке физического лица           | Код физического лица       |
| **Сотрудники** (`Сотрудники`)            | Обычное наименование | Реквизит **«Наименование (PnL)»** в карточке сотрудника                 | Код сотрудника             |
| **Организации** (`Организации`)          | Обычное наименование | Реквизит **«Наименование (PnL)»** в карточке организации                | Код организации            |
| **Банковские счета** (`БанковскиеСчета`) | Обычное наименование | Существующий реквизит **«Наименование в системе P&L»** в карточке счёта | Код банковского счёта      |
| **Пользователи** (`Пользователи`)        | Обычное наименование | Стандартное поле **«Комментарий»** в карточке пользователя              | Слово «Пользователь»       |

Для **Пользователей** отдельное поле «Наименование (PnL)» заполнять не нужно: MCP использует именно комментарий. Заполните поля наименования PnL у тех элементов, для которых хотите видеть понятные псевдонимы вместо кодов. Правило применяется к справочникам, которые есть в вашей конфигурации 1С.

При снятом флажке поиск MCP по организации, контрагенту и банковскому счёту принимает псевдоним или код, а поиск по обычному имени отключён. Если флажок установлен, поиск принимает и обычное имя.

:::info 

Флажок меняет имена перечисленных справочников в ответах MCP. Он **не обезличивает весь ответ**: назначения платежей, комментарии документов, условия оплаты и другие свободные текстовые поля передаются как есть. Псевдонимы и комментарии пользователей тоже могут содержать персональные данные -- проверьте их содержание перед передачей ответов ассистенту.

:::

### Шаг 4. Укажите структуры отчётов

Для показателей ОПиУ, ДДС и бюджетов укажите, какую структуру отчёта брать по умолчанию. Доходы и расходы конкретного проекта по начислению или по деньгам запрашиваются отдельно от этих строк отчётов.

В группе **«ОПиУ»**:

1. **Действует с месяца** -- месяц, с которого действует настройка.

2. **Структура отчета ОПиУ** -- структура, по которой считаются ОПиУ и БДР.

3. **Версия финплана (БДР)** -- версия финансового плана для плановых значений.

В группе **«ДДС»** заполните те же поля для отчёта ДДС и БДДС.

Настройка действует с указанного месяца и до следующей записи. Если структура отчёта в компании менялась, заведите запись на каждый период: ассистент сам выберет структуру, которая действовала в запрошенном месяце. Все записи видны по ссылке **«История»**.

:::info 

Если за запрошенный период структура не указана, ассистент получит ошибку `STRUCTURE_NOT_SET`. Заполните настройку с месяца, с которого в базе есть данные.

:::

Ассистент может запросить и другую структуру, если назвать её в вопросе: «посчитай выручку по структуре „Основная структура P&L“».

### Шаг 5. Подключите ассистента

На компьютере, с которого сотрудник работает с ассистентом:

1. Установите **Node.js** версии 18 или новее с сайта nodejs.org. Для новой установки выбирайте поддерживаемую версию.

2. Скачайте архив с файлами MCP-сервера P&L и распакуйте его в папку, например `C:\PNL-MCP`. Сохраните вместе `index.js`, `package.json`, `package-lock.json` и папку `design`.

3. Откройте терминал в распакованной папке и установите зависимости командой `npm ci`. Если папка поставлена с рабочим `node_modules`, повторная установка не нужна.

4. Добавьте сервер в настройки ассистента. Для Claude Desktop это файл `claude_desktop_config.json` (**Настройки -> Developer -> Edit Config**), для Claude Code -- файл `.mcp.json` в папке проекта:

```json
{
  "mcpServers": {
    "pnl": {
      "command": "node",
      "args": ["C:/PNL-MCP/index.js"],
      "env": {
        "PNL_MCP_URL": "http://<адрес сервера>/<имя публикации>/hs/mcp_pnl/v2",
        "PNL_MCP_USER": "<пользователь 1С из шага 2>",
        "PNL_MCP_PASSWORD": "<пароль>"
      }
    }
  }
}
```

Путь к `index.js` пишется через прямые слеши. Логин на русском языке перекодировать не нужно. Логин и пароль вводите в локальные настройки ассистента; не отправляйте их в чат.

1. Перезапустите ассистента. Список инструментов он получает при запуске.

:::info 

Архив с файлами MCP-сервера P&L: <https://disk.yandex.ru/d/LWMEvaEEKL7NSg>

:::

### Шаг 6. Проверьте подключение

Спросите ассистента: «Проверь подключение к P&L». Он вызовет проверку сервиса и покажет, с какой базой работает, какие структуры отчётов действуют, сколько инструментов доступно и включена ли передача персональных данных (`send_personal_data`).

Проверить сервис без ассистента можно в браузере: откройте адрес `http://<адрес сервера>/<имя публикации>/hs/mcp_pnl/v2/health` и введите логин и пароль пользователя из шага 2.

## Если что-то не работает

| Что видно                                                                                 | Причина или действие                                                                                                            |
|-------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------|
| Ассистент не видит инструментов P&L                                                       | Перезапустите ассистента и проверьте путь к `index.js`. Если модуль Node.js не запускается, выполните `npm ci` в папке сервера. |
| «Нет связи с 1С»                                                                          | Проверьте публикацию базы, публикацию HTTP-сервисов расширений и адрес в `PNL_MCP_URL`.                                         |
| Ошибка 401                                                                                | Проверьте логин и пароль служебного пользователя 1С.                                                                            |
| `TOOL_DISABLED`: «Сервис MCP выключен в настройках модуля»                                | Установите флажок «Использовать MCP сервис».                                                                                    |
| `TOOL_DISABLED`: «Функционал доступен только в версии КОРП»                               | Проверьте версию продукта.                                                                                                      |
| `STRUCTURE_NOT_SET`                                                                       | Укажите структуру отчёта, действующую в запрошенном месяце.                                                                     |
| План по БДР или БДДС нулевой                                                              | Проверьте структуру, в которой заведён план, и настройку действующей структуры.                                                 |
| Вместо имени контрагента, физического лица, сотрудника, организации или счёта показан код | При снятом флажке «Передавать персональные данные» заполните наименование PnL в карточке нужного элемента.                      |
| Вместо имени пользователя показано «Пользователь»                                         | При снятом флажке заполните стандартное поле «Комментарий» у пользователя.                                                      |
| Ассистент не находит организацию, контрагента или счёт по обычному имени                  | При снятом флажке ищите по наименованию PnL или коду.                                                                           |
| Ошибка прав доступа                                                                       | Проверьте роли служебного пользователя из шага 2.                                                                               |
