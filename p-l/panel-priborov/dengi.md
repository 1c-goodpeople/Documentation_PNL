## 1\. Что должно быть готово до первого открытия

Дашборд построен на правиле «движения считаются строго по структуре отчёта» -- без этого он не покажет ни одной цифры по оборотам. Перед первым использованием проверьте:

1. Структура отчёта ДДС по умолчанию должна быть заполнена и актуальна. Если структура не выбрана в настройках, либо её состав статей не покрывает реальные статьи движений в базе -- все обороты (Поступления, Платежи, Денежный поток, Burn Rate, обороты в таблице счетов) будут показывать 0, при этом остатки продолжат считаться корректно (это надёжный признак именно этой проблемы -- «остатки есть, обороты нулевые»).

2. У групп статей ДДС, входящих в структуру, должен быть заполнен реквизит «Вид деятельности». Без него раздел «Поступления и выбытия» (вкладки «Операционная» / «Инвестиционная» / «Финансовая деятельность») останется пустым -- при этом остальной дашборд (KPI, графики, таблица счетов) продолжит работать как обычно, страдает только этот раздел.

   

## Отборы по периодам -- за что отвечает каждый

На форме четыре независимых периода. Каждый управляет своей, не пересекающейся частью дашборда -- смена одного не задевает данные, которые зависят от другого.

| **Отбор**            | **За что отвечает**                                                                                                                                                                                                                                                                                                                                                                                                                 |
|----------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Период**           | Главный период дашборда. Определяет: (1) на конец какой даты считать «Текущий остаток» в KPI-строке; (2) за какой диапазон суммировать «Денежный поток», «Поступления», «Платежи» в KPI-строке; (3) за какой диапазон строится вся таблица «Остатки денежных средств» (открытие/закрытие остатка и обороты по каждому счёту).                                                                                                       |
| **Период сравнения** | Используется только для расчёта процента отклонения (зелёная/красная стрелка рядом с суммой) во всех четырёх KPI-карточках -- сравниваются суммы «Периода» с суммами «Периода сравнения». Сам по себе на экране отдельно не отображается, участвует только в проценте.                                                                                                                                                              |
| **Период графиков**  | Диапазон дат для трёх верхних графиков (Текущий остаток / Денежный поток / Поступления и платежи по периодам) и для раздела «Поступления и выбытия». Единственный период, который работает вместе с переключателем периодичности (неделя/месяц/квартал/год) -- данные на весь диапазон считаются один раз сразу для всех четырёх периодичностей, переключение периодичности внутри дашборда не требует повторного обращения к базе. |
| **Период Burn Rate** | Диапазон, за который считаются показатели правого сайдбара -- Cash Generation/Burn Rate и Runway. Если оставить пустым, по умолчанию берётся тот же диапазон, что и «Период графиков».                                                                                                                                                                                                                                              |

##  Cash Generation / Burn Rate и Runway

Управляется «Периодом Burn Rate». Оба показателя считаются от среднемесячного денежного потока за этот период: СреднемесячныйПоток = (Поступления − Платежи за период Burn Rate) / число месяцев в периоде.

| **Условие**                   | **Что показывается**                                                                            |
|-------------------------------|-------------------------------------------------------------------------------------------------|
| **Среднемесячный поток > 0**  | 💰 «Cash Generation» -- «Компания генерирует денежный поток» (зелёный)                          |
| **Среднемесячный поток = 0**  | 💰 «Cash Generation» -- «Компания не генерирует и не расходует денежные средства» (нейтральный) |
| **Среднемесячный поток \< 0** | 🔥 «Burn Rate» -- «Компания расходует денежные средства» (красный)                              |

**Runway (на сколько месяцев хватит текущего остатка):**

| **Условие**                                                 | **Что показывается**                                                            |
|-------------------------------------------------------------|---------------------------------------------------------------------------------|
| **Текущий остаток ≤ 0**                                     | «0 мес.» -- «Денежный резерв отсутствует» (критично)                            |
| **Среднемесячный поток ≥ 0 (компания не расходует деньги)** | «Не ограничен» -- «Компания генерирует деньги» (хорошо)                         |
| **Runway (= остаток / \|среднемесячный поток\|) \< 3 мес.** | «Высокий риск нехватки денежных средств» (критично)                             |
| **Runway от 3 до 6 мес.**                                   | «Необходимо контролировать денежный поток» (предупреждение)                     |
| **Runway от 6 до 12 мес.**                                  | «Компания сможет функционировать при текущем уровне расходов» (умеренно хорошо) |
| **Runway от 12 мес. и выше**                                | «Компания обладает устойчивым денежным резервом» (хорошо)                       |

4\.4. Раздел «Поступления и выбытия»

Управляется «Периодом графиков» и периодичностью. Четыре вкладки -- Общие, Операционная деятельность, Инвестиционная деятельность, Финансовая деятельность. Внутри каждой вкладки -- один и тот же вид графика (поступления/платежи по периодам), но вкладки, кроме «Общие», показывают только ту часть оборотов, статьи которой классифицированы под соответствующий вид деятельности (см. требование к реквизиту «Вид деятельности» в разделе 1). Если у части статей вид деятельности не определён -- их суммы не попадут ни на одну из трёх вкладок по видам деятельности (но останутся во вкладке «Общие»).

4\.5. Раздел «Остатки денежных средств»

Управляется «Периодом». Таблица со строками-группами (Банковские счета / Кассы / Кошельки / Депозитные счета -- четвёртая группа только если включено «Учитывать депозиты»). Строка группы одновременно -- заголовок и итог по группе (суммы стоят прямо в её ячейках, отдельной строки «Итого» нет). Клик по +/− в начале строки группы разворачивает/сворачивает список конкретных счетов внутри неё. По каждому счёту и по каждой группе показаны: остаток на начало периода, денежный поток за период, поступления за период, платежи за период, остаток на конец периода. Общего итога по всей таблице (по всем группам сразу) нет.

5\. Частые вопросы при настройке

-  «Поменял подразделение/проект/доп. аналитику -- остаток не изменился» -- это ожидаемое поведение: эти три фильтра влияют только на обороты, не на остатки (см. раздел 3).

-  «Все обороты показывают 0, хотя остатки в порядке» -- почти всегда означает, что не заполнена (или заполнена не полностью) структура отчёта ДДС по умолчанию (см. раздел 1, п.1) -- первое, что нужно проверить.

-  «Вкладки по видам деятельности пустые» -- проверьте реквизит «Вид деятельности» у групп статей ДДС, входящих в структуру отчёта (см. раздел 1, п.2). Остальной дашборд при этом работает нормально -- проблема локальная, только для этого раздела.

-  «Не вижу поле Доп. аналитика / Проекты / Депозиты» -- поле скрывается автоматически, если соответствующий раздел отключён в настройках P&L, либо (для депозитов) если база работает не на конфигурации БП.
