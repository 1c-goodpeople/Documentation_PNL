Реестр платежей согласуется **по строкам**. Каждый платёж в реестре проходит маршрут отдельно: один платёж можно согласовать, соседний — отклонить. Этим согласование реестра отличается от заявки на оплату, где решение принимается по документу целиком.

Перед началом должно быть настроено:

- маршрут для типа «Реестр платежей» — см. инструкцию «Настройка маршрута согласования»;
- режим согласования реестра — **«В подсистеме согласования»**. Настройка «Режим согласования реестра платежей» в настройках программы. В режиме «В документе» статус платежам проставляют вручную, без маршрутов.

## Статусы

### Статус реестра

Показан в списке реестров и в самом документе.

| Статус | Что значит |
|---|---|
| Не согласовано | Реестр создан и ещё не отправлялся, или согласование не прошло |
| На согласовании | Реестр отправлен и идёт по маршруту |
| Согласовано автоматически | Согласование завершено через маршрут |
| Согласовано вручную | Статус поставил пользователь вручную. Автоматика его не меняет |

### Статус платежа

Показан в колонке «Статус» таблицы реестра, у каждой строки свой.

| Статус | Что значит |
|---|---|
| Не рассмотрено | Решение по платежу ещё не принято |
| Согласован | Платёж прошёл все этапы маршрута |
| Отклонен | Платёж отклонён на одном из этапов |

## Инициатор: создание и отправка

**Платежный календарь → Реестр платежей → Создать реестр платежей**

1. Укажите дату реестра и режим сбора. При необходимости задайте организацию, направление деятельности, проект и раздел.
2. Заполните таблицу платежей.
3. Нажмите **Провести**.
4. Нажмите **Отправить на согласование**. Откроется окно «Согласование (создание)» со схемой маршрута.
5. Проверьте схему и нажмите **Отправить на согласование**.

После отправки кнопка на реестре сменится на «Отправлен на согласование», реестр получит статус «На согласовании», у всех платежей появится статус «Не рассмотрено».

Если маршрут не подобрался, отправить реестр нельзя. Обратитесь к администратору — для реестра нет подходящего маршрута.

### Как следить за ходом

В таблице реестра у каждого платежа есть две ссылки:

- **Открыть маршрут** — этапы маршрута для этого платежа: на каком этапе он сейчас, кто что решил и кто согласует дальше.
- **Открыть историю** — все события по этому платежу с комментариями.

Над таблицей есть отбор:

- **Все** — все платежи реестра;
- **Согласовано автоматически** — только согласованные;
- **Необходимо согласование** — только те, по которым решение ещё не принято.

## Согласующий: принятие решения

**1C:P&L → Согласование → Мои согласования**

Каждый платёж реестра стоит в списке **отдельной строкой**. У строки видны сумма, контрагент, статья, организация и описание реестра.

Выделите строку — справа откроется карточка:

- **Основное** — объект согласования, инициатор, организация, контрагент, статья, сумма этого платежа, описание. Объект согласования — ссылка на реестр.
- **Файлы** — прикреплённые файлы.
- **Прогресс маршрута** — маршрут **именно этого платежа**: этапы, текущий этап, решения.
- **История** — события **именно этого платежа**.

### Решение

Для реестра доступны две кнопки:

| Кнопка | Что происходит | Комментарий |
|---|---|---|
| Согласовать | Ваш голос по этому платежу засчитан | Необязателен |
| Отклонить | Платёж отклонён и дальше по маршруту не идёт | Обязателен |

**Вернуть на доработку платёж из реестра нельзя.** Реестр собирается из уже существующих платежей: платёж либо проходит, либо нет. Кнопки «Вернуть обратно» для реестра нет.

### Решение по нескольким платежам сразу

Реестры обычно большие. Выделите несколько строк, нажмите правой кнопкой мыши и выберите **Согласовать** или **Отклонить**. Комментарий запишется ко всем выделенным платежам.

## Как движутся платежи по этапам

Каждый платёж идёт по маршруту независимо от остальных.

1. После отправки все платежи получают согласующие этапа 1.
2. По каждому платежу этап закрывается по своему правилу.
3. Согласованный на этапе платёж уходит к согласующим следующего этапа.
4. **Отклонённый платёж дальше не идёт.** Согласующие следующих этапов его не получат.

Поэтому к последнему этапу обычно доходит только часть платежей — те, что прошли все предыдущие.

## Когда согласование реестра завершено

Реестр считается согласованным, когда решение принято по всем платежам. Его статус становится «Согласовано автоматически», платежи получают статусы в платёжном календаре.

**Важно: частично согласованный реестр.** Если из пяти платежей согласованы три, а два отклонены, реестр всё равно получит статус «Согласовано автоматически». По статусу в списке реестров не видно, что часть платежей не прошла. Перед оплатой смотрите статус каждого платежа в таблице реестра или включите отбор «Согласовано автоматически».

## Что делать с отклонённым платежом

Отклонённый платёж в этом реестре так и останется отклонённым. Если платёж после исправления всё-таки нужно провести, включите его в новый реестр и отправьте новый реестр на согласование.

Если отклонены все платежи реестра, реестр получает статус «Не согласовано». Отправить его заново можно из заявки согласования: **Мои согласования → Все заявки**, откройте заявку по этому реестру и нажмите **Отправить повторно**. Реестр пройдёт маршрут с первого этапа.

## Отзыв реестра

Если реестр нужно остановить, пока он на согласовании:

1. **Мои согласования → Все заявки**, откройте заявку согласования по реестру.
2. Нажмите **Отозвать**.

Ожидающие решения снимаются со всех согласующих по всем платежам.

## Ограничения

- Согласованный реестр нельзя пометить на удаление и нельзя отменить его проведение.
- Реестр в статусе «Не согласовано» или «На согласовании» можно править, перепроводить и помечать на удаление.
## Частые вопросы

**Я согласующий, а в списке не весь реестр.** В списке только платежи, которые ждут вашего решения сейчас. Платежи, отклонённые на предыдущих этапах, к вам не придут. Платежи, по которым предыдущий этап ещё не закрыт, придут позже.

**Реестр «Согласовано автоматически», а платёж отклонён.** Так и должно быть: статус реестра показывает, что согласование завершено, а не что прошли все платежи. Статус конкретного платежа — в колонке «Статус» таблицы реестра.

**Почему нет кнопки «Вернуть обратно».** Для реестра платежей возврат на доработку отключён. Отклоните платёж с комментарием, а исправленный включите в новый реестр.
